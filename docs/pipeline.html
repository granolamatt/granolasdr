RX888 ADC hw thread gm/rx888/rx888.h
116-bit real ADC samples, 140 MS/s
2DMA into host ring buffer, block = 700,000 samples = 5 ms
3Signals BufferPosition<int16_t> — HFChannelizer thread wakes
Playback mode (--playback FILE): BufferFile<complex<float>> reads a .dat file and feeds BufferPosition<complex<float>> directly into runPipeline — bypasses RX888 and HFChannelizer.
int16_t ring · 140 MS/s · 700,000 samples/block
HFChannelizer — Wideband FFT & Band Select CUDA thread gm/cuda/HFChannelizer.cc
1H2D copy: int16 → GPU
2Cast kernel: int16 → float32, scale
3Overlap-save wrap: copy tail of previous block to start of fftInData_d
4 R2C FFT: 1,400,000-pt real → complex
bin width = 140,000,000 / 1,400,000 = 100 Hz/bin
output: 700,001 complex bins spanning 0–70 MHz
5 Band bin select: zero-fill channelData_d[65536], then copy 10 HF bands:
160m 18000–20000 80m 35000–40000 60m 53300–54100 40m 70000–73000 30m 101000–101500 20m 140000–143500 17m 180680–181680 15m 210000–214500 12m 248900–249900 10m 280000–297000
6 C2C IFFT: 65,536-pt composite → decimated time domain
output rate = 6,553,600 S/s
7 Overlap-save extract: samples [16384..49152] = 32,768 complex → ring
Record mode (--record FILE): BufferFile<complex<float>> taps this ring and writes to disk with block timing metadata for deterministic replay.
complex<float> ring · 6.5536 MS/s · 32,768 samples/block · all HF bands packed
MagBlock<200> — Normal Ring (FT8 + JS8-Normal) CUDA thread gm/cuda/MagBlock.cc
1 Accumulate: D2D copy blocks → window until buff_pos > 2 × 1,048,576 = 2,097,152 samples
≈ 64 HFChannelizer blocks = 320 ms of data
2 16 FFTs (4 time offsets × 4 freq offsets):
time offset t=0..3start sample = t × 174,720
freq offset f=0..3freqShift by f × 1.5625 Hz
each FFTC2C 1,048,576-pt → 1,048,576 bins
bin width6,553,600 / 1,048,576 = 6.25 Hz (1 FT8 tone)
3 Advance: buff_pos -= 1,048,576 samples
= 160 ms = one FT8 symbol period → fires ~6.25×/sec
4 magKernel: complex → uint8 magnitude
each byte ≈ 20·log₁₀(|z|) + offset (dB-compressed power)
5 D2D ring write: 1 block = 4×4×1,048,576 = 16,777,216 bytes → DeviceRingBuffer
ring wraps at N=200 slots = 3.36 GB on GPU
Ring memory layout:
mag[block × block_stride + (ts×4 + fs) × 1048576 + fo]
block_stride = 4×4×1,048,576 = 16,777,216 bytes
ts = time sub-sample [0..3] | fs = freq sub-sample [0..3] | fo = freq bin [0..1048575]
6 Wideband waterfall: → ZMQ proxy topic ft8/waterfall
FT8Cuda and JS8Cuda-Normal both hold const& DeviceRingBuffer — no second FFT needed. MagBlock owns the ring memory; scanners hold references.
Fast ring (--js8-fast): parallel MagBlock<116> runs from same HFChannelizer output. rfft_len=655,360 · time_osr=2 · freq_osr=2 · N=116 slots · ring=~304 MB. Feeds JS8Cuda<116> → js8.cc (mode="JS8-FAST"). cap_blocks=108 → covers 78 symbols + 30 guard slots.
FT8Cuda — Continuous Scan CUDA thread FT8Cuda.cc · FT8ScanCuda.cu
1 Wakes every 6 blocks (~960 ms)
stride = 6; reads last 106 blocks (16.93 s) from DeviceRingBuffer
2 ft8SyncScanKernel (FT8ScanCuda.cu):
Costas pattern {3,1,4,0,6,5,2} at 3 sync groups
score ≥ min_score → candidate list (fo, to, ts, fs)
3 ft8_soft_symbols_kernel (FT8SoftCuda.cu):
58 data syms × 8 mag bins → 3 LLRs/sym (Gray-coded 8-FSK)
output: log174_d (n × 174 floats)
4 D2H candidates + log174 → decode callback
callback = FT8::decodeAndPublishContinuous() (wired in FT8 constructor)
JS8Cuda<200> — Normal Scan (--js8) CUDA thread JS8Cuda.cc · JS8ScanCuda.cu
1 Reads MagBlock<200> ring (no second FFT)
JS8 Normal epoch = 15 s · ORIGINAL Costas × 3
2 ORIGINAL Costas scan (Normal):
{4,2,5,6,1,3,0} × 3 identical blocks · score ≥ min_score → candidates
3 Soft symbol kernel: LDPC(174,87) LLRs → decode callback
JS8Cuda<116> — Fast Scan (--js8-fast) CUDA thread JS8Cuda.cc · JS8FastScanCuda.cu
1 Reads MagBlock<116> ring (parallel FFT path)
JS8 Fast epoch = 10 s · MODIFIED Costas · rfft_len=655,360
2 MODIFIED Costas scan (Fast/Slow/Turbo/Ultra):
Blk0={0,6,2,3,5,4,1} Blk1={1,5,0,2,3,6,4} Blk2={2,5,0,6,4,1,3}
cap_blocks=108 · time_osr=2 · freq_osr=2 · bin=10 Hz
3 Soft symbol kernel: same LDPC(174,87) → decode callback
decode callback · candidates + log174 (174 floats/cand · ~15 MB typical)
ft8.cc — 15s Window Decoder CPU thread gm/hf/ft8.cc · ft8_lib/
1 LDPC decode: ftx_decode_from_llr()
normalize GPU LLRs · 25-iter BP · (174,91) code · 14-bit CRC
2 Message unpack: 77 bits → callsign1 + callsign2 + grid/report
3 window_buf_ accumulate: best-SNR per callsign
hash_if: callsign hash → window_buf_ key; keep highest score entry
4 flushWindow() every 15 s:
print "[FT8] 15s window: N unique callsigns"
publishDecoded() → ZMQ PUSH to proxy (topic: ft8/decode)
hashtable_cleanup(10): age callsign hash entries
5 RF freq: composite_bin_to_rf_hz() → kBandMap (from kHFBands)
js8.cc — Epoch Decoder (Normal + Fast) CPU thread ×2 gm/hf/js8.cc · ft8_lib/
1 LDPC decode: BP decoder (174,87) M=87 · CRC-12
2 JSC decompress: Huffman → UTF-8 · Frame decode → from_call, text
3 Per-epoch dedup: Normal: floor(unix/15) · Fast: floor(unix/10)
4 publishDecoded() → ZMQ proxy (topic: js8/decode)
JSON payload includes "mode":"JS8" (Normal) or "mode":"JS8-FAST"
ZMQ proxy XSUB:5599 ← producers | XPUB:5600 → consumers · topics: ft8/decode js8/decode
ZMQ Proxy Bus + PSKReporter proxy thread + Python HFRx.cc runProxy() · psk_uploader.py
1 XSUB :5599 ← FT8, JS8, MagBlock waterfall connect here
2 XPUB :5600 → subscribers connect here and filter by topic
3 ft8/decode JSON example:
{"call":"WA9TT","freq":7076397,"snr":-7.0,"unix":…,"offset":3.0}
3b js8/decode JSON example:
{"from":"KD9ABC","text":"…","freq":14076500,"snr":-12.0,"mode":"JS8","unix":…}
mode = "JS8" (Normal, 15 s) or "JS8-FAST" (Fast, 10 s)
4 psk_uploader.py: subscribes to :5600
filters ft8/ and js8/ topics
per-band best-SNR dedup · IPFIX UDP → pskreporter.info:4739 every 5 min
