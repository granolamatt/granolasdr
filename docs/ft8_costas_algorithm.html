2  FT8 Costas Tone Pattern — kCostas[7] = {3, 1, 4, 0, 6, 5, 2}

Symbol index k →

Each Costas symbol k transmits on a single 8-FSK tone bin sm = kCostas[k] (0–7 within the 8-tone group). The pattern forms a Costas array — no two symbols share a row, column, or diagonal, making it easy to distinguish from noise even at low SNR.

static __constant__ uint8_t kCostas[7] = {3, 1, 4, 0, 6, 5, 2}; // FT8 tone bin per sync symbol

// per symbol k:
int sm = kCostas[k]; // expected tone bin (0–7)
int si = (m*7+k) * WINDOW + threadIdx.x; // smem slot base
int cur = smem[si + sm]; // magnitude at Costas tone

For each of 21 symbols (m=0..2, k=0..6):
sm         = kCostas[k] expected tone bin within 8-FSK group (0–7)
cur        = smem[slot + sm] magnitude at expected Costas tone bin
best_other = max( smem[slot + j] ) over all j ∈ 0..7, j ≠ sm  ·  strongest competing tone
score     += cur − best_other max-log soft metric: signal margin over noise floor (int, uint8 units)
num_valid ++ count symbols with block_abs < num_blocks
fscore     = (float)score / num_valid average margin per valid Costas symbol
Emit if fscore ≥ min_score → write (fo, time_off, time_sub, freq_sub, score) via atomicAdd
Intuition: This is the max-log soft metric for non-coherent 8-FSK detection. Each Costas symbol contributes the margin by which the expected tone exceeds the single strongest competitor. A clean signal gives large positive margins; noise keeps all eight bins roughly equal, so margins stay near zero. Averaging over all 21 symbols yields a robust SNR proxy computed entirely from shared memory — no further global reads after the cooperative smem load.

4  Shared Memory Layout — 21 × WINDOW bytes

WINDOW = blockDim.x + 8 = 264 bytes per slot (only first ~11 shown here; total is 264). The highlighted cell is the Costas tone bin for that slot. Threads load cooperatively in stride-blockDim.x pattern so all loads are contiguous (coalesced). Score computation then reads entirely from smem — no further global memory accesses.

⚠ GPU serialization: Both kernels launch with identical grid dimensions (~2M blocks) against the same shared MagBlock<200> ring. When FT8 and JS8 Normal trigger simultaneously (both every 6 ring writes = every ~960 ms), they compete for the full SM array. On the RTX 5060 Ti (SM 12.0) each scan saturates the GPU at ~110 ms alone; serialized, the loser waits then runs — total latency ~220 ms — causing pipeline backlog when --js8-fast adds a third concurrent scan stream.
