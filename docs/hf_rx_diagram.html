CUDA THREAD FT8Cuda — Oversampled Waterfall gm/cuda/FT8Cuda.cc
Processing steps
  • Accumulate input slots into GPU sliding window
  • When window > 2 × rfft_length samples:
  • 16 C2C FFTs: 698,880 pts each — 4 time offsets × 4 freq shifts
    time offset t: start at t × rfft_length/4
    freq shift f: freqShift by f × 1.5625 Hz before FFT
  • magKernel: complex → dB-scaled uint8_t
  • D2D async copy → GPU device ring slot (magFT8_ring_d)
  • Slide window back by rfft_length
  • Every 15 s (trigger at second 14.7 of cycle):
  • cudaEventRecord(ring_ready, stream)
  • scan_stream: waits ring_ready, launches FT8ScanCuda kernel
  • transfer_stream: waits ring_ready, D2H ring snapshot → pinned host
  • Background thread: waits for both, signals ft8.cc

Rolling GPU ring avoids every-other-epoch: trigger snapshots 16.93 s of history every 15 s. On-time signal lands at block ≈ 14. Three-stream architecture keeps main FFT path non-blocking during scan and D2H.

GPU device ring (magFT8_ring_d) · 200 slots × 16 sub-FFTs × 698,880 bins · 2.24 GB GPU
CUDA KERNEL FT8ScanCuda — GPU Costas Sync Scan gm/cuda/FT8ScanCuda.cu · scan_stream
Processing steps
  • Launched at trigger on scan_stream (waits for ring_ready event)
  • Each thread handles one (fo, to, ts, fs) combination:
  • fo: frequency bin 0–698,879
  • to: time offset 0–29 (blocks within capture window)
  • ts: time sub-sample 0–3
  • fs: freq sub-sample 0–3
  • Cooperative smem load: 21 windows × 264 bytes per block (5,544 bytes)
  • Compute Costas score from shared memory — no global reads in compute phase
  • Costas pattern {3,1,4,0,6,5,2} checked at 3 sync groups:
    blocks [to+0..6], [to+36..42], [to+72..78]
  • Score = avg(cur − neighbor) across freq and time neighbors
  • score ≥ 5 → atomicAdd to candidate list
  • cudaEventRecord(scan_done, scan_stream)

Grid layout: sub = blockIdx.y / 30 (slow axis) so adjacent blocks share the same sub-offset — ~86% L2 ring-slot overlap between co-scheduled blocks. Smem tiling eliminates all global reads from the compute phase.

GpuScanResult · ~22K candidates (fo, to, ts, fs, score) · host RAM · + uint8_t waterfall snapshot 4.7 GB pinned
CPU THREAD FT8 Decoder — GPU-primary path gm/hf/ft8.cc · ft8_lib/
Processing steps
  • Receive GpuScanResult + pinned waterfall snapshot from FT8Cuda bg thread
  • GPU path (primary — when gpu->count > 0):
  • Sort all ~22K GPU candidates by score descending
  • Build ftx_candidate_t list directly from GPU results
  • No CPU scan — find=~0 ms
  • CPU fallback (when no GPU results):
  • Multi-threaded ftx_find_candidates_range() across all freq bins
  • Cap at 2,000 candidates
  • Parallel LDPC decode — N CPU threads, round-robin over all candidates:
  • 25 iterations, soft-decision
  • ftx_decode_candidate() — reads waterfall for LLRs
  • Sequential dedup by 22-bit message hash
  • Unpack callsign/grid/report via ftx_message_decode()
  • Print DECODED: line + EPOCH: summary, compute RF frequency
  • Publish JSON to ZMQ PUB socket
  • Age callsign hashtable, reset waterfall
