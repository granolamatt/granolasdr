hf_rx Pipeline

Wideband HF FT8 + JS8 decoder · RX888 → CUDA → ft8_lib → ZMQ proxy → PSKReporter
HARDWARE RX888 MkII SDR gm/rx888/rx888.cc
Operation
  • Direct-conversion ADC, 14-bit real samples
  • USB 3.0 isochronous bulk transfer
  • Writes interleaved int16_t to ring buffer
  • Signals consumer via BufferPosition
Parameters

Typeint16_t
Ring slots16 × NLARGE samples
Coverage0 – 70 MHz

--playback FILE: BufferFile<complex<float>> replays a recorded session; bypasses RX888 and HFChannelizer entirely.

int16_t ring · 16 slots · 140 MS/s real
CUDA THREAD HFChannelizer gm/cuda/HFChannelizer.cc
Processing steps
  • Cast int16_t → float, copy to GPU
  • Overlap input by one slot for continuity
  • Wideband R2C FFT: 1,048,576 points (cuFFT)
  • Zero composite IFFT buffer
  • Copy 10 HF band slices into composite buffer
  • Inverse C2C FFT: 32,768 points
  • Extract center half (16,384 samples), async copy to ring
  • 4 tunable audio sinks → 48 kHz ZMQ streams

--record FILE: BufferFile<complex<float>> taps this edge and writes blocks to disk with pacing metadata for deterministic replay.

complex<float> ring · 16 slots × 16,384 samples · 4.375 MS/s · GPU memory
CUDA THREAD MagBlock — Oversampled FFT & Magnitude Ring gm/cuda/MagBlock.cc
Processing steps
  • Accumulate complex<float> blocks until window ≥ 2 × 698,880 samples
  • 16 C2C FFTs: 4 time offsets × 4 freq offsets
    — time offset t: start at t × rfft_length/4
    — freq offset f: freqShift by f × 1.5625 Hz before FFT
  • magKernel: complex → dB-scaled uint8_t
  • D2D async copy → DeviceRingBuffer slot (uint8_t, GPU)
  • Slide window back by rfft_length (≈ 160 ms, 1 FT8 symbol)
  • Wideband waterfall snapshot → ZMQ proxy (topic: ft8/waterfall)

Fires ~6.25× per second (one FT8 symbol period). Both FT8Cuda and JS8Cuda hold const& to this ring — no second FFT needed.

DeviceRingBuffer<uint8_t, 200> · 2.24 GB GPU · shared by FT8Cuda + JS8Cuda
CUDA THREAD FT8Cuda — Continuous Scan gm/cuda/FT8Cuda.cc
Processing steps
  • Wakes every 6 ring blocks (~960 ms)
  • Reads last 106 blocks (16.93 s) from DeviceRingBuffer
  • FT8ScanCuda kernel: GPU Costas sync scan — Costas pattern {3,1,4,0,6,5,2} at 3 sync groups — score ≥ threshold → candidate list (fo, to, ts, fs)
  • FT8SoftCuda kernel: soft symbols — 58 data symbols × 8 mag bins → 3 LLRs/sym (Gray-coded 8-FSK) — output: log174 (174 floats/candidate)
  • D2H candidates + LLRs → decode callback
  • Callback: FT8::decodeAndPublishContinuous()
Stride6 blocks between scans
Window106 blocks = 16.93 s
Typical candidates~22,000 / scan
Costas pattern{3,1,4,0,6,5,2}
CUDA THREAD (--js8) JS8Cuda — Continuous Scan gm/cuda/JS8Cuda.cc
Processing steps
  • Reads same DeviceRingBuffer (no second FFT)
  • Continuous scan with JS8-specific Costas pattern
  • JS8 Costas scan kernel: Costas pattern {4,2,5,6,1,3,0}
  • Soft symbol kernel: log174 LLRs per candidate
  • D2H → decode callback
  • Callback: JS8::decodeAndPublishContinuous()
Costas pattern{4,2,5,6,1,3,0}
Symbol period~160 ms (same ring)
LDPC code(174,91), M=87
JS8 epoch15 s
decode callback · candidates + log174 (174 floats/cand) · host RAM · ~15 MB typical
CPU THREAD FT8 — 15s Window Decoder gm/hf/ft8.cc · ft8_lib/
Processing steps
  • decodeAndPublishContinuous() called per scan batch
  • LDPC BP decode (ftx_decode_from_llr()): — normalize GPU LLRs, 25-iter belief propagation — (174,91) code, 14-bit CRC check
  • Message unpack: 77 bits → callsign1 + callsign2 + grid/report
  • Accumulate into window_buf_: best-SNR per callsign
  • Every 15 s: flush window — print [FT8] 15s window: N unique callsigns — publish each to ZMQ proxy (topic: ft8/decode) — age callsign hashtable (hashtable_cleanup(10))
Flush period15 s
ZMQ topicft8/decode
ZMQ endpointtcp://localhost:5599 (XSUB)
CPU THREAD (--js8) JS8 — Epoch Decoder gm/hf/js8.cc · ft8_lib/
Processing steps
  • decodeAndPublishContinuous() called per scan batch
  • LDPC BP decode: BP decoder + JSC decompressor
  • JS8 data frame decode: Normal/Compact/Ultra/Turbo frame types
  • Extract from_call, message text, APRS fields
  • Per-epoch dedup: seen_this_epoch_ cleared on 15s epoch rollover
  • Publish to ZMQ proxy (topic: js8/decode)
Epoch period15 s
ZMQ topicjs8/decode

PYTHON PROCESS PSKReporter Uploader psk_uploader.py
Processing steps
  • Subscribe to ZMQ XPUB proxy at tcp://localhost:5600
  • Filter topics ft8/ and js8/
  • Per-band dedup: best-SNR per (callsign, band) per upload window
  • Every 5 minutes: encode IPFIX (flow record) UDP packet
  • Send to report.pskreporter.info:4739
  • Optionally send to analyzer port 14739 (--test)
